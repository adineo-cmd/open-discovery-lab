## Candidate (b): the writer/reader overtake is real, engineered, and computed

The geometry makes the overtake **unavoidable by design** in all four SDK binaries:

- **MID2DWM.EXE**: stream `[0x7E10, 0x13BB0)`; SS base `0x13D1 paras = 0x13D10` (81,489 B) > stream end 80,848 B. The unpacked image necessarily extends past the end of the moved stream — the writer must overwrite the moved stream tail and the moved stub itself. Entry = image offset 0x13600 (79,744 B) likewise sits inside the moved-stream region, i.e. the entry code is **output written over the stream's tail**.
- Using the observed expansion rate r = output/consumed = 17,814/4,081 = **4.363** at the END and solving writer = reader (output = 0x7E10 + output/4.363): the writer overtakes the flag pointer at **output ≈ 41,855 (0xA379)** — well inside the ≥ 83,008-byte image. **Post-overtake flag words are decoded output reinterpreted as tokens: the self-referential phase is designed, not accidental.**
- Siblings confirm the design (stub headers read per-binary, unlike F-56's hardcoded cross-validation): FINDSB stream `[0x2AE0,0x7830)` vs SS 0x86E0 (image floor 28,608/34,528 B) — the writer crosses the stream start at output ≈ 25.7K; PLAYDWD and VOC2DWD likewise have SS base > stream end. In every binary the shift places the stream **inside the image footprint**, so the planned overtake is structural.

## Candidate (a): the bucket map, corrected

The dictionary seen through `es:[bx+di]` is state-dependent, with three regions:

1. **Backward (BX+DI wraps ≥ 0x10000):** dist = 0x10000−BX ≤ 0x2000, source = decoded output at `write_phys − dist`. Always valid post-first-NORM.
2. **Forward (BX+DI does not wrap): source possible only before the first NORM.** After any NORM, DI ≥ 0x2000 and `or bh,0xE0` forces BX ≥ 0xE000, so BX+DI always wraps — **all post-NORM tokens are backward**. F-56's forward formula (stream offset = BX+DI−0x7E10) is therefore valid **only** for MID2DWM's pre-NORM window, where it maps `[0xE000,0xFFFF]` → stream offsets `[0x61F0,0x81F0]` (inside the moved copy). For the siblings (shifts 0x2AE/0x2C7/0x414 paras) the streams sit far below 0xE000, so F-56's forward reading has **no referent** — their sim's forward reads hit unallocated zeros. F-56's sibling cross-validation is consequently invalid; with per-binary headers the "same class of first non-wrapping token at DI 16..42" is an artifact of the shared hardcoded geometry.
3. **New: the old copy serves the dictionary via references at `write+dist` (reverse overtake).** A variant simulation reading forward references at `src = di + dist` (dist = 0x10000−BX, i.e. the same distance field reinterpreted as a forward distance from the write pointer — physically the pristine old-copy region `[write, 0x7E10)` = payload[k], transitioning to the moved copy above 0x7E10) produced real product strings where the F-56 formula produces noise: FINDSB output contains `-95 DiamondW`, `MAD16=iBLA`, `DWS_I11I`, `@ABCDEFG`; VOC2DWD output contains `Run-Time Library`, ` - Copyright (c)`, `2dwd [_<`. This shows the packer's dictionary includes **its own not-yet-consumed stream bytes** — the same bytes later serve as flag/literal data — a second, inverse self-reference: dictionary reads run ~r× ahead of the flag pointer. The exact machine-level encoding of forward references (the tension between `or bh,0xE0`-forced BX ≥ 0xE000 and a write-relative forward distance) is the one open sub-question; the empirical evidence says the write-relative form is what the packer intended.

## The token-2759 END: a structural invariance proof, and what it pins

The END (extended path count byte = 0x00 at stream offset 0xFF0, payload[0xFF0]=00 confirmed) is **invariant under every dictionary variant**: flag words, literal bytes and operand bytes are consumed by SI; token counts are explicit in the bit stream; therefore the output size at any consumed offset (17,814 at consumed 4,081; expansion 4.363) is fixed by the pristine bit stream, and the writer's physical position (17,814; gap to stream start 14,458 B) is fixed with it. Dictionary misreads change copied bytes, never counts, never SI. The flag region `[0x7E10, 0x8E71)` is provably untouched by any write through the END (zero stream hits; writer below image_base+0x4596), and flags read from the old copy would be garbage (the writer overwrites old-copy byte k once output ≥ k, i.e. immediately, at r = 4.36) — contradicting the bit-exact first 36 tokens. **Therefore the divergence that lets the true decoder skip this END must be on the flag-read side itself, and the only remaining freedom is the flag-word base/trajectory coupling with the forward-reference dictionary** — i.e., the same mechanism discovered under (a)(3): if flag words are read through the write-relative stream window rather than a fixed moved-copy base, the flag trajectory becomes output-dependent and the 0xFF0 byte is re-read as data (e.g. as a 129-byte-run count byte payload[0xFEF]=0x80 → c+1 = 129) once the trajectory shifts by even one byte. Re-simulating with the write-relative stream coupling is the single next step; the 170 below-image-base references are consistent with this picture (the packer's window model extends below the image base because its dictionary is the stream, not the output alone).
